# Game Design Document — Elemental Blast

> **Жанр:** Match-3 / Casual Puzzle с элементами защиты «башни»
> **Платформы:** Web (GitHub Pages, Netlify), Android, iOS — портретная ориентация
> **Движок:** Godot Engine 4.6 (Mobile renderer)
> **Разрешение референса:** 648 × 1200
> **Версия документа:** 1.0 (актуальна на 2026‑04‑27)
> **Базовая ветка:** `main`

Этот документ — единая «карта» игровых систем. Он описывает все механики проекта, сложившиеся в коде (`scripts/game_board.gd`, `scripts/LevelManager.gd`, `scripts/level_start_dialog.gd`, `scripts/main_menu.gd` и др.), формат уровней (`levels/level_*.json`) и UI‑экраны. Документ предназначен и как brief для геймдизайнеров, и как технический справочник для инженеров и QA.

---

## 1. High Concept

**Elemental Blast** — это вертикальный match‑3 «снизу вверх», где игрок не двигает фишки, а **тапает кластеры одного цвета** в нижней «зоне игрока», запуская из них **снаряды‑стрелы** в монстров, наступающих сверху. Чем больше фишек в кластере — тем мощнее формируется бонус и больше выстрелов производится по врагам.

Если игрок не успевает «отстреливаться», монстры доходят до **полосы сердец** (полоса между зоной врагов и зоной игрока) и **наносят урон по общему пулу из 10 жизней уровня**. Когда жизни кончаются — игрок может **заплатить золото за восстановление и сдвиг армии назад**, или принять поражение.

### 1.1. Pillars / Опорные принципы

1. **Тап‑match‑3** (без свайпов): простой ввод, читается на телефоне одной рукой.
2. **Tower defense пульс**: каждый ход у игрока — это «выстрел», каждый ход у врага — это «шаг вперёд».
3. **Эскалация мощности**: 6‑7‑8 фишек в кластере → бомба → ракета → радужный шар; объединения бонусов дают «mega‑combo».
4. **Долгосрочная мотивация**: метапрогрессия (золото, бустеры, предуровневые усиления, win‑streak Шлем Морта, золотой пропуск).
5. **Фейл‑тест с откупом**: проиграл — можно докупить ходы или восстановить жизни за монеты (и реальные деньги через магазин).

### 1.2. USP

- Match‑3 не «3‑в‑ряд», а **связные кластеры от 2 фишек** (≥6 даёт бонусы).
- **Combo‑слияния бонусов**: бомба+ракета, радуга+бомба, радуга+ракета, mega‑blast при тройном слиянии.
- **Ходы‑на‑ход**: каждый поп активирует движение всей армии монстров — поле живое.
- **Win streak Шлем Морта** + **Golden Pass с календарной разблокировкой** + **predator‑боусы перед уровнем**.

## 3. Базовый игровой цикл

### 3.1. Macro loop (метапрогрессия)

```
Главное меню
   ↓ (выбор уровня, доступны все из levels/level_001.json … level_050.json)
Диалог старта уровня (Шлем Морта + предуровневые усиления)
   ↓ (выбор бустеров перед уровнем)
Уровень (см. micro loop)
   ↓ (победа / поражение / выкуп)
Награда (золото) → метапрогрессия (Golden Pass, win streak, открытие следующего уровня)
   ↑
Главное меню
```

### 3.2. Micro loop (внутри уровня)

```
Игрок тапает по кластеру однотонных фишек (≥2)
   ↓
Фишки лопаются → запускаются снаряды (по 1 на фишку, со staggered‑задержкой 0.06с)
   ↓
Снаряды летят вверх по колонке, попадают в ближайшего живого врага/препятствие снизу (без оверкилла)
   ↓
Урон по врагам/препятствиям (-1 HP за снаряд)
   ↓
Гравитация снизу‑вверх в зоне игрока + спавн новых обычных фишек сверху ряда зоны игрока
   ↓
Армия монстров делает 1 шаг (если игрок не дал по этой колонке в этот ход / не заморожен)
   ↓
Возможный спавн scheduled_spawns + проверка победы / поражения
```

Правила, влияющие на ход:
- Если в колонке монстра в этом ходу был хотя бы 1 hit (`_enemies_hit_this_turn[y][x] = true`), монстр **не двигается** этим ходом (это «штраф» за получение урона).
- Если в колонке нет хита — монстр пытается шагнуть строго вниз. Если впереди препятствие или другой монстр — пробует обойти горизонтально (см. §6.5).
- Если монстр стоит на ряду сердец `_heart_row_y = ENEMY_ROWS - 1`, при следующем ходе он атакует игрока.

## 4. Игровое поле

### 4.1. Координатная сетка

- **8 колонок** `x ∈ [0..7]`, **16 рядов** `y ∈ [0..15]`.
- **Зона врагов:** `y ∈ [0..ENEMY_ROWS-1] = [0..9]`. Клетки **ниже**, чем у игрока (40 px по высоте), позволяют разместить больше монстров.
- **Полоса сердец (heart strip):** ниже зоны врагов, не является клеткой; высота 52 px. Здесь рисуется глобальная шкала жизней `TOTAL_LIVES_PER_LEVEL = 10`.
- **Зона игрока:** `y ∈ [ENEMY_ROWS..ROWS-1] = [10..15]` — 6 рядов высотой 80 px каждая.

### 4.2. Содержимое клеток

Каждая клетка хранит свой тип в массивах:
- `chips[y][x]` — индекс фишки в зоне игрока:
  - `-1` — пусто
  - `0..3` — обычные цвета (Red, Blue, Green, White)
  - `RAINBOW_CHIP_IDX = -2` — радужный шар
  - `ROW_BONUS_CHIP_IDX = -3` — стрела/ракета
  - `BOMB_CHIP_IDX = -4` — бомба
- `enemies[y][x]` — текущий HP монстра в зоне врагов (0 если пусто).
- `enemies_initial_hp[y][x]` — стартовый HP монстра (для отрисовки полоски здоровья и для зачёта целей).
- `obstacles[y][x]` — HP препятствия в зоне врагов (0 если пусто).
- `obstacles_unbreakable[y][x]` — флаг «стены» (тип `wall` — неразрушимое препятствие).

### 4.3. Цвета и текстуры фишек

```
0 — Красный   (Chip_Base_Red.png)
1 — Синий     (Chip_Base_Blue.png)
2 — Зелёный   (Chip_Base_Green.png)
3 — Белый     (Chip_Base_White.png)
```

Бонусные фишки используют отдельные текстуры (`Chip_Bonus_Bomb.png`, `Chip_Bonus_Arrows.png`, `Chip_Bonus_Rainbow_Ball.png`).

## 5. Match‑3 механика

### 5.1. Кластер и пороги

Алгоритм лопания: BFS/DFS по 4‑связности соседей одного цвета (`_pop_cluster`), стартуя с тапа.

| Размер кластера | Эффект |
|---|---|
| 1 | Не лопается (`MIN_NORMAL_CLUSTER_POP = 2`) |
| 2–5 | Лопается, без формирования бонуса |
| **6** | На месте тапа создаётся **бомба** (`BOMB_CHIP_IDX`) |
| **7** | Создаётся **ракета** (`ROW_BONUS_CHIP_IDX`) |
| **≥ 8** | Создаётся **радужный шар** (`RAINBOW_CHIP_IDX`) |

Все фишки кластера превращаются в снаряды (по одному на фишку), вылетающие со staggered‑задержкой `0.06s`. Цель — ближайший живой монстр / препятствие в **той же колонке** снизу вверх (см. §6.4).

### 5.2. Бонусные фишки (одиночная активация)

#### 🧨 Бомба `BOMB_CHIP_IDX`
- **Эффект:** взрыв «крестом» — центр + 4 соседних клетки (вверх/вниз/влево/вправо).
- **Каждая** из 5 клеток триггерится через `_trigger_chip_at`, что:
  - выпускает 1 снаряд по колонке (если в ней есть цель),
  - если в клетке стоит другой бонус — рекурсивно активирует и его (через цепочку `match type`).
- VFX: круговая ударная волна `bomb_explosion` + 12 искр‑частиц с гравитацией.

#### ➡️ Ракета `ROW_BONUS_CHIP_IDX`
- **Эффект:** уничтожает весь горизонтальный ряд `row_y` в зоне игрока, посылая по снаряду из каждой колонки.
- VFX: горизонтальный «луч» через всю ширину поля.

#### 🌈 Радужный шар `RAINBOW_CHIP_IDX`
- **Эффект:** выбирает **самый частый цвет** на поле (`_get_most_frequent_color_idx`), при равенстве — случайный из топа, и триггерит **все** фишки этого цвета через `_trigger_chip_at`.
- VFX: «радужные нити» из шарика к каждой целевой фишке.

#### Создание бонуса при поп‑клике

Бонус физически создаётся **в той клетке, по которой игрок кликнул** (а не в случайной). Таким образом игрок может «крафтить» бонусы в нужных колонках.

### 5.3. Объединения бонусов (combo)

Когда игрок тапает по бонусной фишке, и рядом по 4‑связности есть ещё бонусы, активируется `_check_and_execute_bonus_combine`:

1. Алгоритм собирает **связную ортогональную группу** всех бонусов (`_collect_connected_bonus_component`).
2. Если в группе есть **уникальные комбинации** — играется специальный сценарий:

| Состав группы | Эффект |
|---|---|
| 🌈 + 🧨 + ➡️ | **Mega Blast** — взрывается всё поле игрока партиями по 6 фишек с задержкой 0.08с |
| 🌈 + 🧨 | **Rainbow + Bomb**: все фишки самого частого цвета превращаются в **бомбы**, потом детонируют партиями по 4 |
| 🌈 + ➡️ | **Rainbow + Rocket**: все фишки самого частого цвета превращаются в **ракеты**, потом детонируют партиями по 4 |
| 🧨 + ➡️ | **Bomb + Rocket**: 3 горизонтальных ряда (центр ±1) подряд + 3 вертикальных «столба» (центр ±1) |

Если уникальной комбо‑пары нет — каждая клетка группы триггерится **по отдельности** через свой эффект (две бомбы рядом → две независимые крестовые детонации, две радуги → две зачистки, и т.д.). Это правило ключевое: **поп по кластеру одинаковых бонусов лечит» сразу все** (см. memories.md).

### 5.4. Спавн обычных фишек

После лопания применяется «гравитация снизу‑вверх» (`_apply_gravity_up`): пустые клетки в зоне игрока поднимаются вверх, фишки сверху падают на их место. Затем `_spawn_new_chips_with_fall` заполняет верхний ряд зоны игрока (`y == ENEMY_ROWS`) случайными цветами из `CHIP_COLORS`.

> **Замечание:** нумерация рядов считается «сверху вниз», но визуально зона игрока — «снизу», поэтому новые фишки появляются «у границы с врагами» и эффект ощущается как падение сверху.

### 5.5. Стартовый спавн бонусов (`_spawn_bonus_chips_at_start`)

При старте уровня в случайные клетки зоны игрока подмешиваются:
- бонусы от **Шлема Морта** (см. §10) — стрелы и бомбы;
- бонусы от **выбранных предуровневых усилений** (см. §11) — стрела/бомба/радуга.

Все они подменяют **обычные фишки**, не накладываются друг на друга.

## 6. Враги (монстры)

### 6.1. Тиры монстров (по HP)

Уровни «силы» монстра определяются стартовым HP, текстуры — пять штук:

| HP | Текстура | Условные стат-иконки |
|----|----------|----------------------|
| 1 | `Monster_1_lvl.png` | базовый |
| 2 | `Monster_2_lvl.png` | боец |
| 3 | `Monster_3_lvl.png` | толстяк |
| 4 | `Monster_4_lvl.png` | элита |
| 5+ | `Monster_5_lvl.png` | босс / минибосс |

Цвет полоски здоровья: зелёный (`HEALTH_BAR_HEALTH_COLOR`) → красный (`HEALTH_BAR_DAMAGE_COLOR`) пропорционально текущему HP / `enemies_initial_hp`. Над монстрами с `hp >= 4` рисуются «трещины» (`_draw_monster_cracks`) при получении урона, плюс случайные shake‑анимации.

### 6.2. Размещение и спавн

Конфигурация уровня хранится в `levels/level_NNN.json`. Используются 2 механики:

#### `start_monsters`
Монстры, которые уже стоят на поле в начале уровня:
```json
"start_monsters": [
  {"x": 2, "y": 1, "hp": 1},
  {"x": 4, "y": 1, "hp": 1},
  {"x": 3, "y": 2, "hp": 2}
]
```

#### `scheduled_spawns`
«Порталы» — клетки, в которые монстры будут появляться **после N ходов игрока**:
```json
"scheduled_spawns": [
  {"x": 2, "y": 0, "hp": 1, "count": 1, "spawn_after_player_turns": 1},
  {"x": 2, "y": 0, "hp": 1, "count": 1, "spawn_after_player_turns": 2}
]
```

- `y == 0` — классический «портал» в верхнем ряду.
- Любое другое `y` — спавн «изнутри поля» (если клетка свободна и без препятствия).
- Поле `_player_turn_counter` инкрементируется на ходе игрока, не на ходе монстра.

### 6.3. Идл‑анимация и ХП‑бар

`_process(delta)` всегда активен, чтобы:
- проигрывать слабую покачивающуюся idle‑анимацию монстров (через `_monster_shakes`),
- анимировать снаряды (`_projectiles`),
- движение врагов (`_enemy_move_anims`),
- анимации смерти (`_enemy_death_anims`),
- VFX (`_board_vfx`).

### 6.4. Снаряды (`_enqueue_projectiles`)

Алгоритм планирования цели:
1. Для колонки `col_x` строится массив `hp_left[y]`: HP препятствия (если есть) или HP монстра в каждой строке зоны врагов.
2. Учитываются уже летящие снаряды (чтобы не было оверкилла): `hp_left[y] -= кол-во летящих снарядов в эту клетку`.
3. Каждый из `count` снарядов выбирает **самую нижнюю клетку с `hp_left > 0`** (т.е. ближайшего врага) и резервирует её, уменьшая `hp_left`.
4. Если ни одной живой клетки нет — снаряд летит «в небо» (`has_target = false`) и просто пропадает.

Каждый снаряд:
- Триггерит `_enemy_move_pending = true` (если `trigger_move = true`), что запустит ход монстров после завершения серии.
- Имеет `delay = base_delay + i * 0.06`, чтобы выглядеть как «очередь».
- Цвет золотистый `Color(1.0, 0.85, 0.2, 1.0)`.

### 6.5. Движение монстров

`_plan_enemy_moves()` строит план **на один тик**:
- Идёт сверху вниз по `y` (от `ENEMY_ROWS-1` к `0`).
- Если монстр был «ранен в этом ходу» (`_enemies_hit_this_turn[y][x] = true`) — стоит на месте.
- Если монстр на ряду сердец `_heart_row_y` — отмечается **атака** (`outcome = "attack_player_life"`) с предупреждением (см. §6.6).
- Иначе — пытается шагнуть вниз (`y+1`):
  - если клетка свободна и не препятствие → идёт.
  - если ниже препятствие/занято — обходит горизонтально через `_horizontal_detour_direction_order`.
- Алгоритм обхода (`_find_detour_exit_column_below_obstacle`): BFS по связной группе препятствий снизу, ищет ближайшую колонку с проходом и выбирает направление (стабильно, без рандома).

Это даёт «змеевидное» поведение: монстр движется к ближайшему «обходу» и постепенно стекает вниз по канавкам.

### 6.6. Атака и предупреждение

Перед атакой по сердцу:
1. `_enemy_attack_warn_pending = true`, на `ENEMY_ATTACK_WARN_DURATION = 0.55` сек.
2. Атакующая клетка мигает красным с частотой `ENEMY_ATTACK_WARN_FLASH_HZ = 5 Гц`.
3. По окончании предупреждения:
   - `_player_lives_remaining -= 1`,
   - shockwave + shake камеры,
   - монстр перемещается в `m.ty` (последний ряд / «прорыв»).

После прорыва клетка снова становится «фронтом», но монстр остаётся на ней. Если жизней не осталось → переход к экрану «поражение».

### 6.7. Прорыв и pending breach

Если в момент прорыва армия пробила ряд сердец, монстры запоминаются в `_pending_breach_monsters[column]`. После «оплаты восстановления»:
- клетка с прорванным сердцем восстанавливается,
- цели уровня инкрементируются под спасшегося монстра (`_increment_level_target`),
- pending‑монстры размещаются на ряду сердец (или на свободной клетке),
- вся армия сдвигается на `REFILL_ENEMY_SHIFT_ROWS = 3` ряда к спавну (т.е. вверх).

> Важная тонкость: для столбцов с сердцем спавн «сверху» отключён (см. memories.md), но монстры над `_heart_row_y` всё равно планируют ход — иначе они «застревают» под стенами.

## 7. Препятствия / стены (obstacles)

Размещаются только в зоне врагов. Два типа:

### 7.1. Разрушаемые (`type: "breakable"` или без поля)
- Имеют `hp` (обычно 2–5) и собственный health bar.
- Снаряды и бонусы наносят им урон **раньше**, чем монстрам в той же колонке.
- При достижении HP = 0:
  - клетка очищается;
  - проигрывается VFX взрыва;
  - если задано `spawn_on_destroy: {hp, count}` — спавнится 1+ монстр в этой клетке (см. memories.md);
- Блокируют движение монстров — те обходят горизонтально.
- Не блокируют спавн `scheduled_spawns` (если вокруг есть свободные клетки), но не позволяют спавнить **в клетке препятствия**.

### 7.2. Неразрушаемые стены (`type: "wall"`)
- HP не имеют, не отображают полоску.
- Блокируют снаряды (снаряд в эту колонку ищет цель **выше** стены, либо «над» ней).
- Блокируют движение монстров — обход обязателен.
- Для них в генераторе кампании используется правило «змейка»: `enforce_wall_row_gaps` — плотные ряды стен чередуют проход слева/справа по порядку y.

### 7.3. Конфигурация JSON
```json
"obstacles": [
  {"x": 4, "y": 3, "hp": 2},
  {"x": 3, "y": 0, "type": "wall"},
  {"x": 2, "y": 5, "hp": 3, "spawn_on_destroy": {"hp": 1, "count": 1}}
]
```

## 8. Цели уровня и условие победы

Цели уровня — **выбить определённое число монстров каждого типа (HP)**:
- При старте `_rebuild_level_targets_from_field` собирает счётчик `{hp → count}` по всем стартовым монстрам **и** по `scheduled_spawns`.
- При смерти монстра `_decrement_level_target_for_init_hp(initial_hp)` уменьшает соответствующий счётчик.
- При спавне через scheduled — счётчики уже содержат вклад этого монстра, ничего не добавляется.
- При «возрождении» монстра через `spawn_on_destroy` или после `_apply_defeat_refill_paid` — счётчики **увеличиваются** (`_increment_level_target_for_init_hp`).

### Условие победы (`_check_level_completed`)
1. `_level_ready_for_win == true` (страховка от ложных срабатываний на старте).
2. Не открыт диалог поражения.
3. Все цели обнулены (`_level_targets[hp] == 0` для всех HP).
4. Очередь спавнов пуста (`_monster_spawn_queue.is_empty() && _scheduled_spawns.is_empty()`).

> Важно: **препятствия и обычные фишки** не нужно убирать для победы. Это намеренное решение, чтобы игрок не «доходил» уровень до пустого поля, а фокусировался на врагах.

### Условие поражения
- `_player_lives_remaining <= 0` после прорыва → диалог `_show_level_end_defeat_no_lives`.
- В том же диалоге игрок может нажать «Восстановить» и заплатить золото — см. §8.1.

### 8.1. Платное восстановление
Цены и объём пополнения шкалы зависят от номера попытки в текущей сессии уровня (`_defeat_refill_index`):

| Попытка | Стоимость, монет | +жизней |
|---|---|---|
| 0 | 300 | 3 |
| 1 | 600 | 5 |
| 2 | 900 | 7 |
| 3 | 1200 | 10 |

Дополнительно: после оплаты вся армия сдвигается на 3 ряда к спавну (`REFILL_ENEMY_SHIFT_ROWS`). Заморозка не активируется.

### 8.2. Покупка ходов
В играх с лимитом `moves` (если задан в конфиге уровня): когда `_moves_left == 0`, появляется диалог покупки ходов:
- 1‑я покупка: 100 монет → +5 ходов
- 2‑я: 250
- 3‑я: 400
- N‑я: `100 + 150*(N-1)`

(см. `docs/coins_system.md`).

## 14. Golden Pass (золотой пропуск)

См. также memories.md и `LevelManager.gd`.

### 14.1. Концепция

Календарный батл‑пасс на 30 уровней (`GOLDEN_PASS_TIER_COUNT = 30`) с двумя колонками наград — **бесплатной** и **премиум**. Премиум открывается за 499 монет (`GOLDEN_PASS_PREMIUM_PRICE_COINS`) или через реальную покупку (стаб).

### 14.2. Разблокировка тиров

Срабатывает раз в **новый календарный день** при первом входе:
- `tick_golden_pass_daily_login()` сравнивает текущий `YYYY-MM-DD` с `golden_pass_last_calendar_date`.
- Если день новый — `golden_pass_unlocked_tiers += 1` (но не выше `GOLDEN_PASS_TIER_COUNT`).
- Первый зафиксированный день — стартовый: количество разблокированных тиров **не растёт сразу** в этот же день.

### 14.3. Награды (по тирам)

`get_golden_pass_tier_reward(tier_index)` возвращает `{free, premium}`. Каждая запись — `{kind: ..., ...}`:

- `coins`: `{"kind":"coins","amount": N}` — добавляет монеты.
- `booster`: `{"kind":"booster","id":"hammer|row_blast|shuffle|freeze","amount": N}`.
- `bonus_chip`: `{"kind":"bonus_chip","id":"bomb|arrow|rainbow","amount": N}` — увеличивает запас предуровневых усилений.

В коде есть **жёстко прописанные 30 строк наград** (`get_golden_pass_tier_reward`). Любая корректировка экономики правит таблицу там.

### 14.4. Забор наград

- `claim_golden_pass_free(tier_index)` / `claim_golden_pass_premium(tier_index)` — по одному.
- `claim_all_golden_pass_rewards()` — массово; делает **одно сохранение** и эмитит сигналы `coins_changed` / `boosters_changed` / `golden_pass_state_changed` ровно один раз при необходимости.
- В UI оверлея `golden_pass_dialog.gd`:
  - сетка наград из 2 колонок × 30 строк;
  - на иконке бесплатной/премиум каждая клетка содержит «название → квадратный 88px бокс с артом → подпись».
  - кнопка «ЗАБРАТЬ ВСЁ» внизу панели (`GoldenPassClaimAllBar`) появляется при `get_golden_pass_pending_claim_count() > 0`.
- Сигнал `golden_pass_state_changed` НЕ вызывает `setup()`/`free()` дерева — используется `refresh_from_state()` → `_rebuild_all()` (избегает падения во время клика «Забрать»).

### 14.5. Точка входа

На главном экране — круглый FAB (Floating Action Button) под верхним баром в правом верхнем углу. Иконка/бейдж пульсирует, если есть pending‑награды.

## 15. Туториал на уровне 1

## 17. Кампания и левел‑дизайн

### 17.1. Структура файлов

`levels/level_001.json` … `levels/level_050.json`. Перегенерация — `python3 tools/generate_campaign_levels.py` (содержит ассерт `assert_wall_row_gaps`).

### 17.2. Поля JSON

| Поле | Описание |
|---|---|
| `cols` / `rows` | 8 / 16 (захардкожено в коде) |
| `enemy_rows` | 10 (информационно) |
| `moves` | Лимит ходов (опционально) |
| `seed` | Сид для случайностей (старт чипов и т.п.) |

| `scheduled_spawns` | Массив `{x,y,hp,count,spawn_after_player_turns}` |
| `obstacles` | Массив `{x,y,type,hp,spawn_on_destroy}` |

### 17.3. Прогрессия сложности (примеры)

- **Уровень 1:** 3 стартовых монстра HP=1–2, 3 портала с интервалом 1–3 хода. Туториал ON.
- **Уровень 10:** плотный стартовый строй (24 монстра HP=2–3 в рядах 2–4), длинная очередь scheduled (16 спавнов вплоть до HP=6), вертикальные стены `x=3,5` сверху вниз и горизонтальная стена `y=9` (порталы по флангам).

- **Уровни 40–50:** боссы (HP 5–8) + плотная очередь спавна, ходов мало (10–15), требует grand‑combo со стартовыми бонусами.

### 17.4. Открытие уровней

- `current_level` хранит «следующий к прохождению».
- `max_unlocked_level` — наивысший доступный (после `mark_level_completed`).
- Список доступных номеров: `get_available_level_numbers()` сканирует `res://levels/level_*.json`.

- `shake` — общий тряс камеры.
- `particle` — точечные частицы с гравитацией.
- `chip_pop` — лопание фишки (через `_add_chip_pop_vfx`).

Дополнительно: `_monster_shakes[id]` — индивидуальное покачивание монстра (idle и hit), `_enemy_death_anims` — пульс при смерти, `_active_anims` — рост/появление новой фишки/бонуса.

Музыки и звука пока в проекте нет — это пункт в roadmap.

## 22. Производительность и совместимость

- Целевой FPS: 60 на современных мобильных, 30+ на бюджетных Android.
- Web‑экспорт: включён mobile renderer; не использует тяжёлые шейдеры; все эффекты — процедурные `_draw()`-операции.
- Поле перерисовывается через `queue_redraw()` только при изменении состояния (поп фишки, движение монстров, VFX‑тики).
- `set_process(true)` остаётся включённым всегда для idle‑покачиваний — это «бутылочное горлышко» при большом количестве монстров; стоит мониторить на 50+ монстрах.

## 23. QA / тест‑план (high level)

Критические сценарии:

1. **Match‑3 пороги:** поп 5/6/7/8 фишек → отсутствие бонуса, бомба, ракета, радуга.
2. **Combos:** комбинации всех 7 пар/троек бонусов (см. таблицу в §5.3).
3. **Снаряды без оверкилла:** 8 снарядов в колонку с 1 монстром HP=3 → ровно 3 наносят урон, 5 пропадают «в небо».
4. **Препятствия + обход:** монстр над одиночной стеной, над цепочкой стен, перед `wall + monster`. Ожидаем «змейку».
5. **Прорыв и платное восстановление:** жизни → 0, кнопка «Восстановить», 4 уровня цены.
6. **Шлем Морта:** 3 победы подряд → max уровень → бонусные фишки на старте.
7. **Предуровневые усиления:** покупка, отмена выбора, 0‑заряд → диалог покупки.
8. **Golden Pass:** разблокировка нового тира при смене календарного дня (мокать `Time`), `claim_all` сразу 5+ наград без падений.
9. **Сохранение:** перезапуск приложения сохраняет монеты, бустеры, win streak, разблокированные уровни.
10. **Туториал level 1:** запуск, прохождение всех фаз, повторный заход на уровень 1 — туториал снова есть.
11. **Editor mode:** запуск тестового уровня → возврат через «Назад» в редактор (`finish_editor_test`).

См. также: `docs/dialog_testing_checklist.md`, `docs/health_bar_test_scenarios.md`.

## Приложение B. Жизненный цикл уровня (псевдокод)

```
on enter level:
    LevelManager.start_next_level / restart_current_level
    config = get_level_config(current_level)
    init chips()  # случайные обычные фишки в зоне игрока
    init obstacles_from_config(config)
    init enemies_from_config(config)
    rebuild_level_targets_from_field()
    init_player_lives_for_level()  # = TOTAL_LIVES_PER_LEVEL
    show level_start_dialog -> on "ИГРАТЬ"
        spawn_bonus_chips_at_start(mort+prelevel)
        _level_ready_for_win = true
    if level == 1: start tutorial overlay

loop until win/lose:
    on user click in player zone:
        cluster = pop_cluster(x,y)   # см. §5.1, §5.3
        gravity_up + spawn_new_chips
        for each cell in cluster: enqueue_projectiles
        _enemy_move_pending = true

    on projectiles finished:
        if _enemy_move_pending and not freeze:
            plan_enemy_moves -> [moves]
            if any attack_player_life: warn 0.55s, then apply_enemy_moves_from_plan
            else: apply_enemy_moves_from_plan
            _player_turn_counter += 1
            process_scheduled_spawns()

    check win/lose:
        if check_level_completed: _on_level_completed()
        elif lives <= 0: _show_level_end_defeat_no_lives()

on win:
    reward = 50 + count_bonus_chips_on_player_field()*10
    LevelManager.add_coins(reward)
    LevelManager.mark_level_completed()  # win_streak++ , update mort

on lose & user pays refill:
    apply_defeat_refill_paid()
    armies shifted up by 3 rows
    pending breach restored
    continue play

on lose & user gives up:
    LevelManager.mark_level_failed()
    return to main_menu
```
